### これが問題である理由(実例)

**q69 は `mirrored` 承認だったが、PR #126 で一次ソースに当て直したら3つの不正確さが出た。**

1. 「採光のための開口部が床面積の7分の1以上」— 実際は「**採光に有効な部分の面積**」(開口部の面積 × 採光補正係数)
2. 「照明設備を設けたら10分の1まで緩和」— 実際は「10分の1**までの範囲内で大臣が別に定める割合**」(10分の1は下限)
3. 「学校の教室は5分の1」— 実際は施行令19条3項の表(一)が列挙する学校に限られ、大学等は10分の1

**同じことが記録の無い64問にも起きうる。** これが #125 の残作業の実質的な意味。

## 3. PR #127 で入ったスキーマ

`types/index.ts`:

```ts
export type SourceLevel = "primary" | "mirrored" | "secondary" | "unverified";

export type SourceRef = {
  level: SourceLevel;        // 問題全体(lesson を含む)の最も弱い水準。網羅集計はこれ
  answerLevel?: SourceLevel; // 肢の正誤を決める根拠の水準。F8 はこちらで判定。未指定は level と同じ
  fileId?: string;           // 様式など、法令本体と別に管理されるものの識別子
  note?: string;
};

export type DriftChecked = "not_required" | "checked" | "analysed" | "unchecked";

export type LawVersion = {
  revisionId?: string;       // e-Gov の Law RevisionID
  verifiedAgainst?: string;  // 照合に用いた版の施行日 (YYYY-MM-DD)
  examBasisDate?: string;    // その年度の試験の法令基準日 (YYYY-MM-DD)
  driftChecked?: DriftChecked;
  note?: string;
};

export const SOURCE_LEVEL_RANK: Record<SourceLevel, number> = {
  primary: 3, mirrored: 2, secondary: 1, unverified: 0,
};
```

`lib/questions.ts` の `normalizeQuestion` が読み込み境界で **fail-closed に正規化**する。

| 未指定 | 既定値 |
|---|---|
| `verified` | `false` |
| `source` | `{ level: "unverified" }` |
| `source.answerLevel` | `source.level` と同じ |
| `lawVersion` | `{ driftChecked: "unchecked" }` |

**既定値は必ずコピーを返す**(共有オブジェクトを返すと1回の書き換えで既定値そのものが汚染される)。

### `driftChecked` の使い分け(ここを間違えた)

- `not_required` — 照合に使った版の**施行日と法令基準日が一致**する場合**だけ**
- `checked` — 基準日時点の版と突き合わせて差分なしを確認した
- `analysed` — 差分はあるが本問に影響しないと判断した(理由を `note` に)
- `unchecked` — 未確認(既定)

**「施行日が基準日より前だから差分確認不要」は成り立たない。** それは「基準日までに効力を
生じた」ことしか示さず、「基準日時点でもその内容のまま」であることを示さない。
PR #126 でこの誤りをやって Codex に指摘された。整合性テストで検査している。

### 追加済みのテスト

`data/questions/integrity.test.ts`:
- `source.level` / `driftChecked` が読み込み境界で必ず埋まっている
- `answerLevel` が `level` より弱いことはない

## 5. 作業のときに効く前提

### 環境

- **e-Gov / Wikibooks に接続できない**。条文原文は承認者に貼ってもらう
- PDF を読むときは `pypdf`。縦書き告示は1文字ずつ改行されるので `re.sub(r'[\n\r]+','',t)` で連結する
- `pdftoppm` は無いので `Read` ツールの PDF レンダリングは使えない

### 絶対に守るもの(`CLAUDE.md` より)

- **AIの下書き照合だけを根拠に `verified: true` にしない**。最終判断は人が原文を見て行う
- `data/questions/index.ts` は**末尾追記のみ**。既存の配列順を動かさない
  (`Attempt` 履歴が `(questionId, choiceIndex)` で紐付いている)
- 既出問題の `choices[].segments` を書き換えて**肢の意味を変えない**。法的精度の補足は
  `lesson` か `explanation` 側で行う(PR #126 でこの判断をした)
- 問題データの文字列に **Markdown は使えない**。`lesson` は `<li>` にプレーンテキストで
  描画されるだけ(`components/LessonAccordion.tsx`)。表を書きたいときは散文にする
- `reference/` 配下は編集・import・ビルド対象にしない

### レビュー対応で学んだこと

- **F1: レビューの「おすすめ書き換え」を無条件採用しない。** 一次ソースに当ててから適用する
  - 実例: PR #122 で「閲覧所の根拠は規則5条ではなく5条の2」という指摘が来たが、
    原文を確認したら**指摘のほうが誤り**だった。断定的に書き換えていたら誤りを埋め込んでいた
  - 逆に PR #122 の C1(76条の引用)では、**こちらの照合記録が部分引用で壊れていて**、
    正しい指摘を誤って却下しかけた。記録も無条件には信頼しない
- 照合シートを部分更新するときは、**同じ論点に触れている他の箇所も必ず見る**。
  このシリーズだけで「承認欄だけ更新して上の記述が古いまま」という不整合を4回出した
- 「原文」と書くなら**省略記号を使わない**。要約と逐語引用は明示的に分ける
